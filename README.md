# Умный кредитный кабинет — общий репозиторий

Это общий репозиторий MVP для хакатона. `frontend`, `backend` и `scoring` здесь являются **Git submodules**: каждый путь указывает на конкретный коммит собственного репозитория, а не содержит копию его истории или файлов.

| Модуль | Отдельный репозиторий |
| --- | --- |
| `frontend/` | [smart-credit-frontend](https://github.com/Tilekbeki/smart-credit-frontend) |
| `backend/` | [smart-credit-backend](https://github.com/Tilekbeki/smart-credit-backend) |
| `scoring/` | [smart-credit-scoring](https://github.com/Tilekbeki/smart-credit-scoring) |

Три модуля собираются в один учебный пользовательский сценарий. Фронтенд показывает предложение и заявку; бэкенд сохраняет её и управляет статусами; scoring рассчитывает объяснимое решение на синтетических данных. Сборка и запуск описаны ниже.

## Получить проект вместе с модулями

Для клонирования нужны права доступа ко всем четырём приватным репозиториям.

```sh
git clone --recurse-submodules https://github.com/Tilekbeki/smart-credit.git
```

Если общий репозиторий уже клонирован:

```sh
git submodule update --init --recursive
```

## Запустить весь кабинет

Требуются Docker и Docker Compose. Из корня общего репозитория:

```sh
docker compose up --build
```

Откройте [http://localhost:8080](http://localhost:8080). В интерфейсе можно выбрать вымышленную компанию, подобрать финансирование, проверить контактные данные, отправить заявку, дождаться автоматического решения, принять условия и получить средства на **тестовый счёт**. Отправленная заявка и её события сохраняются в Docker volume `backend_data` и доступны после перезапуска контейнеров. Тестовый код входа указан в [README фронтенда](frontend/README.md) и не показывается на экране входа.

В другом терминале можно проверить всю серверную цепочку, включая сохранение и повторное чтение заявки:

```sh
python3 scripts/smoke.py
```

Скрипт создаёт одну синтетическую заявку через публичный адрес кабинета и доводит её до условного зачисления.

Здесь используются только синтетические компании, расчётные правила и условное зачисление. Кабинет не подключён к банку, не оформляет настоящий кредит и не переводит реальные деньги. Успешный путь проходит без обращения к менеджеру; при отказе или встречном предложении показывается итоговое решение и доступные действия.

Для остановки нажмите `Ctrl+C` в терминале с Compose. Повторный запуск сохраняет тестовые заявки. Чтобы удалить их вместе с контейнерами и локальным томом, выполните `docker compose down -v`.

`frontend` доступен только на `127.0.0.1:8080`. Nginx отдаёт собранное приложение и пересылает `/api/` во внутренний сервис `backend`, который обращается к внутреннему `scoring`. Хранилище бэкенда находится в `/data/applications.sqlite3` внутри Docker volume. Для локальной разработки каждого сервиса смотрите README соответствующего модуля.

## Работа с изменениями

Разрабатывайте код в соответствующем дочернем репозитории и отправляйте изменения туда. После этого обновите указатель в общем репозитории отдельным коммитом:

```sh
git submodule update --remote frontend   # или backend / scoring
git add frontend
git commit -m "Update frontend submodule"
git push
```

Общий репозиторий фиксирует версии трёх модулей для совместной сборки. Новый коммит в дочернем репозитории не меняет указатель здесь автоматически.

## CI

CI кода запускается независимо в каждом дочернем репозитории. CI общего репозитория проверяет только `.gitmodules` и указатели на коммиты при их изменении; для этого ему не нужно скачивать приватные дочерние репозитории или хранить дополнительный токен.

Используйте только синтетические данные. Не добавляйте реальные персональные или банковские данные в исходники и тесты.
