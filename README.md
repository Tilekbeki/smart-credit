# Умный кредитный кабинет — общий репозиторий

Общий рабочий репозиторий MVP для хакатона. Три модуля лежат рядом и могут разрабатываться вместе:

| Папка | Назначение | Отдельный репозиторий |
| --- | --- | --- |
| `frontend/` | Интерфейс предпринимателя и сотрудника банка | [smart-credit-frontend](https://github.com/Tilekbeki/smart-credit-frontend) |
| `backend/` | API, заявки и интеграция со скорингом | [smart-credit-backend](https://github.com/Tilekbeki/smart-credit-backend) |
| `scoring/` | Объяснимый скоринг; пока безопасная заглушка | [smart-credit-scoring](https://github.com/Tilekbeki/smart-credit-scoring) |

Начальное содержимое модулей скопировано из трёх отдельных репозиториев. Их Git-истории в этот репозиторий не вложены. Код пока является стартовым каркасом: backend и scoring не выдают кредитное решение, а frontend ещё не подключён к API.

## Локальный запуск и проверки

- Frontend: откройте `frontend/index.html` в браузере.
- Backend: `cd backend && python3 -m backend.app` — `http://localhost:8000/health`.
- Scoring: `cd scoring && python3 -m scoring.app` — `http://localhost:8001/health`.
- Тесты backend: `cd backend && python3 -m unittest discover -s tests -v`.
- Тесты scoring: `cd scoring && python3 -m unittest discover -s tests -v`.

Контракт запроса scoring v1 хранится в `backend/contracts/scoring.schema.json` и `scoring/contracts/scoring.schema.json`. При изменении обновляйте обе копии в одном PR. CI проверяет их совпадение.

## CI

Для каждого модуля настроен отдельный GitHub Actions workflow с фильтром путей для `push` и `pull_request`:

- Изменения в `frontend/` запускают только Frontend CI.
- Изменения в обычном коде `backend/` или `scoring/` запускают CI соответствующего модуля.
- Изменение любой копии общего scoring-контракта запускает Backend CI и Scoring CI: обе стороны API должны быть согласованы.
- Изменение файла workflow запускает соответствующий CI. Правки только этого README или `.gitignore` не запускают проверки кода.

Если появятся общие код или конфигурация, добавьте их пути в фильтры всех затронутых workflow. При настройке обязательных проверок ветки учитывайте, что workflow, пропущенный фильтром путей, может оставить обязательный check в состоянии ожидания.

## Связь с отдельными репозиториями

Этот репозиторий и три отдельных репозитория **не синхронизируются автоматически**. После изменения модуля перенесите те же изменения в соответствующий отдельный репозиторий отдельным PR, если команда продолжает использовать оба варианта. Для изменений контракта перенесите обновление в оба сервисных репозитория. Не считайте один из вариантов актуальным без проверки коммитов.

Используйте только синтетические данные. Не добавляйте реальные персональные или банковские данные в исходники и тесты.
